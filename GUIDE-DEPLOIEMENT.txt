=============================================================================
  NODE.47 — GUIDE DE MISE EN LIGNE GRATUITE
  Netlify (le site) + Supabase (la base de données) + GitHub (le passage
  de relais) — aucun paiement, aucune carte bancaire.
=============================================================================

LES 3 ÉTAPES :
  Étape A — GitHub   : le coffre-fort où sera déposé votre code (une fois)
  Étape B — Supabase : la base de données en ligne de votre site
  Étape C — Netlify  : le serveur qui affiche votre site sur Internet

DURÉE TOTALE : environ 1 heure, tranquille, avec un café.
À PRÉPARER : le dossier du code source décompressé (l'archive
NODE47-source-code.zip), un bloc-notes pour y copier 3 informations.

Avant de commencer, notez dans votre bloc-notes :
  1. Le mot de passe que vous voulez utiliser pour votre /admin
     (choisissez-en un FORT : au moins 12 caractères, chiffres et symboles)
  2. Cette clé secrète (vous pouvez la copier telle quelle) :
     node47-cle-7f3a9b2c8d1e4f6a9b0c2d4e6f8a1b3c-k47

=============================================================================
ÉTAPE A — DÉPOSER LE CODE SUR GITHUB (environ 15 minutes)
=============================================================================
A1. Allez sur  https://github.com  → cliquez « Sign up » (inscription).
    Utilisez votre adresse email, créez un mot de passe, suivez les
    instructions de vérification.

A2. Une fois connecté : cliquez le « + » en haut à droite de l'écran,
    puis « New repository » (nouveau dépôt).

A3. Remplissez ainsi :
    - Repository name :  node47
    - Laissez coché « Public »
    - NE cochez AUCUNE des cases du bas (ni README, ni .gitignore,
      ni licence)
    - Cliquez « Create repository ».

A4. Sur la page qui s'affiche, cliquez le lien
    « uploading an existing file » (téléverser un fichier existant).

A5. Ouvrez votre dossier « NODE47-source-code » décompressé.
    Sélectionnez TOUT son contenu (Ctrl+A) et glissez-déposez-le
    dans la zone de dépôt de GitHub.

    ⚠️ IMPORTANT — deux règles :
    - Il faut déposer le CONTENU du dossier (les dossiers src, prisma,
      public, deploiement, et les fichiers package.json, netlify.toml...),
      PAS le dossier parent.
    - GitHub limite à 100 fichiers par dépôt. Votre dossier en contient
      environ 200 : déposez d'abord LA MOITIÉ, cliquez « Commit changes »
      en bas de page, puis revenez sur la page du dépôt, refaites
      « Add file » → « Upload files » et déposez le reste.

A6. Après le dernier « Commit changes », vérifiez : la page du dépôt doit
    montrer les dossiers  src, prisma, public, deploiement, scripts  et les
    fichiers  package.json, netlify.toml  directement à la racine.
    Si vous voyez un dossier unique qui contient tout, dites-le moi.

=============================================================================
ÉTAPE B — CRÉER LA BASE DE DONNÉES SUPABASE (environ 15 minutes)
=============================================================================
B1. Allez sur  https://supabase.com  → « Start your project » → créez un
    compte (le plus simple : « Continue with GitHub » avec le compte
    créé à l'étape A).

B2. Cliquez « New project » puis :
    - Name :  node47
    - Database Password : cliquez « Generate a password », COPIEZ ce mot
      de passe dans votre bloc-notes (titre : « mot de passe Supabase »).
      Vous en aurez besoin juste après.
    - Region :  Europe (Frankfurt)  ou similaire (le plus proche pour un
      public francophone)
    - Cliquez « Create new project » et patientez ~2 minutes.

B3. CRÉER LES TABLES (obligatoire) :
    - Dans le menu de gauche, cliquez « SQL Editor » puis « New query ».
    - Ouvrez le fichier  deploiement/01-creer-les-tables.sql  (dans le
      dossier du code source), copiez TOUT son contenu, collez-le dans
      l'éditeur SQL.
    - Cliquez « Run » (ou Ctrl+Entrée).
    - Résultat attendu : « Success. No rows returned » → parfait.

B4. (OPTIONNEL) RETROUVER VOS ANALYSES DÉJÀ SAISIES :
    Même manipulation avec le fichier  deploiement/02-remplir-avec-mes-
    donnees.sql  → « Run ». Vos 11 analyses actuelles apparaîtront en
    ligne. Si vous préférez partir d'une base vierge, ignorez ce fichier.

B5. RÉCUPÉRER L'ADRESSE DE LA BASE :
    - En haut de l'écran, cliquez le bouton « Connect ».
    - Dans le panneau qui s'ouvre, cherchez la section
      « Connection pooling » (ou « Transaction pooler »).
    - Copiez la ligne « URI » qui ressemble à :
      postgresql://postgres.abcdefghij:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
    - Collez-la dans votre bloc-notes.

B6. FINALISER L'ADRESSE (toujours dans votre bloc-notes) :
    - Dans l'adresse copiée, remplacez  [YOUR-PASSWORD]  par le mot de
      passe Supabase noté en B2 — SANS les crochets.
      (Si ce mot de passe contient des caractères spéciaux comme @ # ? :
      remplacez @ par %40, # par %23, ? par %3F, : par %3A)
    - À la FIN de l'adresse, ajoutez :  ?pgbouncer=true&connection_limit=1
    - Résultat final attendu (exemple) :
      postgresql://postgres.abcdefghij:MonMotDePasse@aws-0-eu-central-1.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
    → C'est votre DATABASE_URL. Gardez-la dans le bloc-notes.

=============================================================================
ÉTAPE C — METTRE LE SITE EN LIGNE SUR NETLIFY (environ 15 minutes)
=============================================================================
C1. Allez sur  https://app.netlify.com  → « Sign up » → choisissez
    « Log in with GitHub » et autorisez Netlify.

C2. Cliquez « Add new site » (ou « Add new project ») →
    « Import an existing project » → « Deploy with GitHub ».
    Si Netlify demande l'accès : autorisez (bouton « Configure Netlify
    on GitHub » → « All repositories » ou sélectionnez node47).

C3. Cliquez sur votre dépôt « node47 ».
    Netlify affiche un écran de réglages. Il doit détecter Next.js tout
    seul. La commande de build vient de votre fichier netlify.toml —
    n'y touchez pas.

C4. AVANT de cliquer « Deploy », cherchez la section
    « Environment variables » (parfois sous « Advanced ») et cliquez
    « Add a variable » pour ajouter ces 4 variables, une par une :

    Clé :  DATABASE_URL
    Valeur : collez l'adresse préparée en B6.

    Clé :  ADMIN_PASSWORD
    Valeur : le mot de passe fort noté avant de commencer.

    Clé :  ADMIN_SECRET
    Valeur : la clé secrète notée avant de commencer.

    Clé :  NEXT_PUBLIC_SITE_URL
    Valeur : https://node47.netlify.app
    (adaptez selon le nom de site que Netlify proposera ; si le nom est
    différent, mettez-le simplement en minuscules, sans espace)

C5. Cliquez « Deploy node47 » (ou « Deploy site »).
    Patientez 3 à 6 minutes — vous voyez l'avancement en direct.

C6. Quand le statut passe à « Published » (vert), cliquez l'adresse du
    site affichée en haut :  VOTRE SITE EST EN LIGNE.

C7. Vérifiez :
    - La page d'accueil affiche vos analyses → tout est bon.
    - https://VOTRE-NOM.netlify.app/admin → connectez-vous avec
      ADMIN_PASSWORD → publiez une analyse test → elle apparaît.

APRÈS LA MISE EN LIGNE — LE FONCTIONNEMENT QUOTIDIEN
=============================================================================
Vous n'avez PLUS BESOIN du serveur local pour publier.
  - Publier une édition : connectez-vous à https://VOTRE-NOM/admin
    et travaillez comme d'habitude. Tout ce que vous publiez s'affiche
    immédiatement sur le site public.
  - L'adresse à donner à vos lecteurs : https://VOTRE-NOM.netlify.app

Ce qui reste gratuit à vie (avec les limites largement suffisantes) :
  - Netlify : 100 Go de trafic par mois (un site comme le vôtre en
    consomme une fraction infime) et 300 minutes de construction.
  - Supabase : 500 Mo de base (vos analyses en occupent ~0,05 Mo).
  - GitHub : dépôts publics illimités.

⚠️ LE SEUL PIÈGE À CONNAÎTRE — la mise en veille de Supabase :
  Supabase gratuit met la base « en sommeil » après 7 jours sans
  AUCUNE activité. Publier vos éditions ou avoir des visiteurs compte
  comme une activité : en pratique, ça ne s'activera jamais.
  Mais si le site affiche un jour une erreur de base de données :
  1. Connectez-vous à supabase.com
  2. Votre projet est marqué « Paused » → cliquez « Restore project »
  3. Attendez 2 minutes → le site revient tout seul.
  Aucune donnée n'est perdue pendant une mise en veille.

Chaque fois que vous redéposerez une nouvelle version du code sur GitHub
(nouvelle archive ZIP fournie), Netlify reconstruira et publiera le site
automatiquement en quelques minutes.

=============================================================================
PROBLÈMES FRÉQUENTS ET SOLUTIONS
=============================================================================
- « Deploy did not succeed » sur Netlify :
  Site configuration → Deploys → cliquez le déploiement en rouge →
  faites défiler les journaux, copiez les lignes en rouge et envoyez-les moi.

- Le site s'affiche mais sans aucune analyse :
  → la base est en veille (voir le piège ci-dessus), OU les tables n'ont
  pas été créées : refaites l'étape B3.

- Erreur « Invalid environment variables » juste après le déploiement :
  → une variable est mal orthographiée ou incomplète. Site configuration →
  Environment variables : vérifiez DATABASE_URL (elle doit commencer par
  postgresql:// et finir par ?pgbouncer=true&connection_limit=1),
  ADMIN_PASSWORD, ADMIN_SECRET, NEXT_PUBLIC_SITE_URL. Après correction :
  Deploys → « Trigger deploy » → « Clear cache and deploy site ».

- Vous avez modifié une variable mais rien ne change :
  → Deploys → « Trigger deploy » → « Clear cache and deploy site »
  (obligatoire après chaque changement de variable).

- L'adresse /admin affiche « not found » :
  → c'est normal si vous n'êtes pas connecté : allez sur /admin/login.
